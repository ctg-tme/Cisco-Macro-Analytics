# Use a versioned Analysis Report as the canonical output

Each analysis will produce a portable JSON Analysis Report with an explicit schema version, and the product interface will render that report rather than maintain a separate result model. Findings are structured records with stable rule identities, evidence classifications, independent Review Priorities, source ranges, normalized evidence, basis, limitations, recommended actions, and relevant schema references; prose and aggregates are derived from those records. The report identifies files and ranges but does not embed original source text, which the local interface reads directly from the in-memory Macro Set. Parse failures, missing imports, and unresolved dependencies become Coverage Gaps in a partial report whenever any usable evidence remains; only a submission from which no usable Macro Set can be parsed is an Analysis Failure. Export requires an explicit user action and does not transmit the report automatically. Maintaining a stable report contract adds versioning and migration responsibilities, but prevents UI, tests, exports, and future clients from assigning different meanings to the same analysis.
