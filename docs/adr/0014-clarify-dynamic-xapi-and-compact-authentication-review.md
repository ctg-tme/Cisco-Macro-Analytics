# Clarify Dynamic xAPI References and compact authentication review

The user-facing name for an xAPI Binding Flow that cannot be completely reconstructed from source is Dynamic xAPI Reference. The stable rule code and internal observation kind remain unchanged so existing Analysis Report consumers can continue to identify the rule. The Finding is Advisory rather than Warning because runtime construction can be an intentional, valid abstraction. Its copy must say that the analyzer cannot verify the complete path, direct the Macro Author to review and test injected content on the target device before release, and identify the constructed path as an early troubleshooting point if an error occurs.

Authentication Vocabulary Match remains one Warning Finding per macro and retains every exact Source Reference. The interface must not render every source-preview control at once. It presents one unmasked local source location at a time with previous and next navigation while preserving total occurrence counts and exact matched terms. Because multiple vocabulary matches can share one displayed source line, the interface states both the matched-phrase and deduplicated source-location totals. A Macro Author may dismiss a reviewed location as not concerning and restore dismissed locations; dismissal is reversible, exists only in the current local analysis review, resets when a new analysis starts, and never changes the canonical Finding or Analysis Report export. Analysis Report exports continue to omit source excerpts and adjacent literal values.

This decision supersedes the xAPI Flow Frontier user-facing term and Warning priority in ADR 0011, and refines the local authentication-source presentation established by ADR 0013. It does not change Seeded xAPI Data Flow, Partial Observation Coverage, credential matching, or the stable Finding rule identities.
